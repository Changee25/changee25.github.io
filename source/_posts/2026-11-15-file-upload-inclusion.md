## 一、文件包含

### 1. 生活里的比喻

假设我们去一家公司前台说：

> “帮我拿一下 3 号文件。”

前台去档案室，把 `3 号文件` 拿给咱们。

正常流程是：

用户说文件名 → 前台去指定档案柜拿 → 交付

但如果前台做事不思考，和他说：

> “帮我拿一下 `../财务室/工资表.txt`”

他也不检查，直接跑到隔壁财务室拿给我们。这就是**目录穿越**。

`..` 的意思是“上一级目录”。
`../` 就是“先回到上一层，再进入别的目录”。

### 2. 代码大概长什么样

PHP 里常见这种写法：

```
$page = $_GET['page'];
include("pages/" . $page . ".php");
```

正常访问：

```
?page=home
```

实际包含：

```
pages/home.php
```

但如果访问：

```
?page=../../secret/flag
```

实际路径就变成了：

```
pages/../../secret/flag.php
```

中间的 `../` 会一层层往上跳，最后可能跳到 `pages/` 外面。

### 3. 为什么危险

文件包含的危险分两层：

**第一层：读到不该读的文件。**

比如配置文件、数据库密码、源代码、密钥、日志，甚至系统文件。

**第二层：执行不该执行的代码。**

如果被包含的文件里含有 PHP 代码，PHP 不只是“读出来”，还会**执行它**。

所以：

- 包含一个 `.txt`：通常只是把内容显示出来。
- 包含一个 `.php`：里面的 PHP 代码会被执行。

这就是为什么 LFI（本地文件包含）有时能升级成 RCE（远程代码执行）。

### 4. LFI 和 RFI

- **LFI**：Local File Inclusion，本地文件包含。
  包含服务器本地的文件，比如 `../../secret.txt`。
- **RFI**：Remote File Inclusion，远程文件包含。
  包含攻击者自己服务器上的文件，比如 `http://evil.com/shell.txt`。
  这需要服务器开启“允许远程包含”，现代 PHP 一般默认关闭，所以 RFI 没有以前常见。

**LFI 更常见，RFI 条件更苛刻。**

### 5. 怎么修

核心原则：**不要让用户输入直接变成文件路径。**

不要这样：

```
include("pages/" . $_GET['page'] . ".php");
```

改成“名字 → 固定文件”的映射：

```
$pages = [
    'home'    => __DIR__ . '/pages/home.php',
    'about'   => __DIR__ . '/pages/about.php',
    'contact' => __DIR__ . '/pages/contact.php',
];

$page = $_GET['page'] ?? 'home';

if (!isset($pages[$page])) {
    exit('页面不存在');
}

include $pages[$page];
```

这样用户只能说 `home`、`about`、`contact`，不能说 `../../secret`。

如果业务确实需要拼路径，就要：

1. 用 `realpath()` 得到真实路径；
2. 检查这个路径是否仍然在允许的目录里面；
3. 不在就拒绝。

另外，PHP 的远程包含应该关闭：

ini

```
allow_url_include = Off
```

## 二、文件上传

### 1. 生活里的比喻

文件上传就像公司收发室：

> 有人寄来一个包裹，收发室不检查，直接放进办公室。

如果包裹里只是普通文件，没问题。
但如果包裹里是危险物品，或者包裹本身能被当成“工作人员”使唤，那就出事了。

文件上传功能本身不是漏洞。
**真正的漏洞是：服务器太信任用户上传的文件。**

### 2. 代码大概长什么样

PHP 里常见这种写法：

```
move_uploaded_file(
    $_FILES['file']['tmp_name'],
    "uploads/" . $_FILES['file']['name']
);
```

这段代码做了三件事：

1. 接收用户上传的文件；
2. 用用户提供的文件名；
3. 保存到 `uploads/` 目录。

如果没有任何检查，用户就能上传任意文件。

### 3. 三种常见风险

**第一种：上传可执行脚本，拿到服务器权限。**

如果：

- 上传目录在网站根目录下面；
- 服务器会执行 PHP；
- 上传目录有执行权限；

那攻击者上传一个 `.php` 文件，再访问它，服务器就可能执行里面的代码。这就是常说的“上传木马”或“GetShell”。

**第二种：上传 HTML / SVG，造成存储型 XSS。**

即使服务器不执行 PHP，上传一个 `.html` 文件也可能有问题。

如果网站这样返回：

```
Content-Type: text/html
```

浏览器就会把上传的 HTML 当成网站自己的页面执行。里面的 JavaScript 可以：

- 读取页面内容；
- 以当前用户身份发请求；
- 修改页面；

**第三种：覆盖文件、塞满磁盘、托管恶意文件。**

比如上传同名文件覆盖配置，或者上传大量大文件把磁盘撑满，或者把网站当成恶意软件下载站。

### 4. 为什么“只检查后缀”不够

如果这样写：

```
if (pathinfo($name, PATHINFO_EXTENSION) === 'jpg') {
    // 允许上传
}
```

因为攻击者可以：

- 改后缀：`shell.php` 改成 `shell.jpg`；
- 伪造 `Content-Type`：请求里写 `image/png`，但内容不是图片；
- 利用黑名单漏掉的后缀：只禁了 `.php`，可能还有别的可执行后缀；
- 上传 `.htaccess` 之类的配置文件，改变服务器行为；
- 上传 SVG，里面带脚本。

所以不能只信：

- 文件名；
- 扩展名；
- 浏览器发来的 `Content-Type`。

这些都能被用户控制。

### 5. 比较靠谱的检查顺序

1. **先登录/鉴权**：不是谁都能上传。
2. **限制大小**：防止塞满磁盘。
3. **扩展名白名单**：只允许业务需要的类型，比如 `.png`、`.jpg`。
4. **检查文件头**：文件开头几个字节是“身份证”，比如 PNG 有固定开头。
5. **图片重新编码**：把图片重新生成一遍，去掉夹带的内容。
6. **随机文件名**：不要用用户给的名字，防止覆盖和特殊字符。
7. **存到 Web 根目录之外**：上传目录不要能被 URL 直接访问。
8. **禁止执行**：即使文件进了上传目录，服务器也不要把 `.php` 当程序跑。
9. **下载时鉴权**：通过后端控制谁能看、以什么类型返回。

## 三、这两个漏洞经常一起出现

它们可以组合：

```
先上传一个文件
      ↓
再用文件包含去包含它
      ↓
服务器执行文件里的代码
```

或者：

```
上传目录在网站根目录
      ↓
直接上传可执行脚本
      ↓
访问这个脚本
      ↓
服务器执行
```

所以真实渗透测试里，文件上传和文件包含经常被放在一起看。

## 四、一张表区分它们

|              | 文件包含                  | 文件上传                       |
| ------------ | ------------------------- | ------------------------------ |
| 用户控制什么 | 读哪个文件                | 传什么文件                     |
| 常见入口     | `?page=...`、`?file=...`  | 上传表单                       |
| 核心问题     | 用户输入直接拼进路径      | 服务端信任上传文件             |
| 常见结果     | 读源码/配置，可能执行代码 | 存储型 XSS，可能 RCE           |
| 修复关键词   | 白名单映射、路径校验      | 类型白名单、内容校验、禁止执行 |
