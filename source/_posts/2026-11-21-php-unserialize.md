## 一、序列化

**序列化就是将一个对象转换成字符串。该字符串包括该类的属性名，属性值，属性类型（string,int......）和该对象对应的类名，目标是是把对象转成字节流或文本。函数:serialize()  **

```java
class Person {              // ← 类名：Person
    String name = "张三";    // ← 属性名 name，属性类型 String，属性值 "张三"
    int    age  = 25;       // ← 属性名 age， 属性类型 int，   属性值 25
}
```

结果

```
Person{name:String="张三", age:int=25}
```

鹅鹅鹅 还是用php

```php
class Person
{
    public string $name = "张三";
    public int    $age  = 25;
}

$p = new Person();
$s = serialize($p);
echo $s;
// O:6:"Person":2:{s:4:"name";s:6:"张三";s:3:"age";i:25;}
```

私有/受保护属性名会被“改名”：私有属性变成 `\0类名\0属性名`，受保护属性变成 `\0*\0属性名`（`\0` 是 NUL 字节）

##### **私有属性**

```php
class CC {
    private $pass = 'pass';
}
```

实际：

```
\0 CC \0 pass
│  │   │  └── 属性名 pass（4 字节）
│  │   └───── 第二个 NUL（1 字节）
│  └───────── 类名 CC（2 字节）
└──────────── 第一个 NUL（1 字节）
```

**属性长度 + 2 + 类名长度** 就是 `4 + 2 + 2 = 8`，即

```
s:8:"\0CC\0pass"
```

##### 受保护属性

```php
protected $pass = 'pass';
```

实际

```
\0 * \0 pass
│  │  │  └── 属性名 pass（4 字节）
│  │  └───── 第二个 NUL
│  └──────── 字面量 *（1 字节）
└─────────── 第一个 NUL
```

**属性长度 + 3**，即 `4 + 3 = 7`，即

```
s:7:"\0*\0pass"
```

## 二、反序列化

**反序列化是序列化的逆过程，把存储或传输格式重新解析成内存中的对象或数据结构**

举个🌰：

```
class Person
{
    public string $name = '张三';
    public int $age  = 25;
}

// 序列化：对象 → 字符串
$s = serialize(new Person());
// O:6:"Person":2:{s:4:"name";s:6:"张三";s:3:"age";i:25;}

// 反序列化：字符串 → 对象
$p = unserialize($s);
var_dump($p);
```

结果

```
object(Person)#2 (2) {
  ["name"]=> string(6) "张三"
  ["age"]=>  int(25)
} 
```

### 1.反序列化漏洞

**程序把不可信输入当作序列化数据来反序列化，攻击者借此控制“实例化哪个类、给属性赋什么值”，再让程序自己触发的魔术方法（`__destruct`、`__wakeup`、`__toString`…）执行恶意逻辑，最终实现任意文件写入、任意命令执行、SSRF 等。**

#### 产生条件

1. 应用程序使用unserialize() 函数处理用户输入
2. 输入数据未经过充分验证
3. 存在可利用的魔术方法或对象方法调用链

#### 魔术方法

按用途分类五组：

##### 1. 生命周期

| 方法            | 触发时机                                      |
| --------------- | --------------------------------------------- |
| `__construct()` | `new` 创建对象时                              |
| `__destruct()`  | 对象销毁时（脚本结束、`unset`、引用计数归零） |
| `__clone()`     | clone  对象实例时（在副本上调用）             |

##### 2. 属性访问拦截

| 方法        | 触发时机                                       |
| ----------- | ---------------------------------------------- |
| `__get()`   | **读取**不存在或不可访问的属性                 |
| `__set()`   | **写入**不存在或不可访问的属性                 |
| `__isset()` | 对不可访问或不存在属性做 `isset()` / `empty()` |
| `__unset()` | 对不可访问或不存在属性做 `unset()`             |

##### 3. 方法调用拦截

| 方法         | 触发时机                           |
| ------------ | ---------------------------------- |
| `__call()`   | 调用不存在或不可访问的**实例方法** |
| `__invoke()` | 把对象当函数用                     |

##### 4. 字符串化与调试

| 方法           | 触发时机         |
| -------------- | ---------------- |
| `__toString()` | 对象被当字符串用 |

##### 5. 序列化专用

**只有调用 `serialize()` / `unserialize()` 时，引擎才会自动调用它们**

| 方法              | 触发时机           | 备注                            |
| ----------------- | ------------------ | ------------------------------- |
| `__sleep()`       | `serialize()` 前   | 返回要序列化的属性名数组        |
| `__wakeup()`      | `unserialize()` 后 | 反序列化后立刻调用              |
| `__serialize()`   | `serialize()` 时   | **PHP 7.4+，优先于 `__sleep`**  |
| `__unserialize()` | `unserialize()` 时 | **PHP 7.4+，优先于 `__wakeup`** |

### 2.POP链

pop链（Property-Oriented Programming Chain,面向属性编程链）是反序列化漏洞利用的核心技术，核心思想是通过控制对象的属性值，引导程序执行流经过多个类的调用，最终触发危险动作。

> 在**不注入任何自定义代码**的前提下，攻击者利用目标应用中**已存在的类**（称为 gadget）及其**魔术方法**，通过对**反序列化对象图（object graph）中属性值的精确控制**，构造出一条**由引擎自动触发的调用链**，从某个入口魔术方法出发，经由若干 个类逐级转发，最终到达危险操作。

这个有点像多米诺骨牌吧，程序里本来就有很多牌（方法），反序列化让我们能把牌摆成一条线，这个时候只需要推倒第一张（触发 `__destruct`）就可以让最后一张正好落在“执行命令”上。
